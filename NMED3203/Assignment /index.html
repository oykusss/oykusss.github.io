# Running Out — Design rationale ## Idea Running Out asks the participant to fill a canvas with shapes. Pressing and holding grows a shape; releasing stamps it permanently. Every mark claims the round space around it and spends ink from one shared pot. The piece asks one question: do you make a few bold marks or many small ones, knowing that each choice decides what you can still do? ## Agency × Possibility Agency lives in the hold-to-grow gesture: the participant chooses where a mark goes, how big it becomes and which shape it takes. Possibility lives in two limits, claimed space and ink. The premises depend on each other because these limits are produced by the participant's own earlier actions: a large circle placed early becomes a wall that stops the next shape from growing. Acting spends possibility, and the shrinking space of possibility makes each next action more deliberate. Free mode removes only the space rule, so comparing the two modes shows what Possibility adds. ## Theory Wardrip-Fruin et al. (2009) separate triggering an event from agency, which needs an intention that the system visibly answers. A tap-to-stamp tool would only trigger, so I made size something the participant holds and decides, with the ink cost shown before release. Their account, however, treats agency as intentions being satisfied; my piece deliberately blocks intentions, and the paper says little about frustration as the experience itself. Gaver (1991) describes affordances as relations between a person and an environment that can be perceptible, hidden or false. Without the dashed circles, claimed space would look free, a false affordance, so I drew every claim and an "×" cursor on blocked spots. Hold-to-grow, though, remains a hidden affordance carried only by the instruction line. ## What I learned My first version gave each tool six stamps and shrank each mark as the tool ran out. Testing it, I noticed that every session ended the same way: twenty-four stamps, whatever I chose. My actions spent possibilities but never decided which ones disappeared. I replaced the counters with claimed space and shared ink, so earlier choices now shape later ones. --- **Live link:** https://oykusss.github.io/NMED3203/assignment/ ## References - Gaver, W. W. A quick tap makes the smallest mark. - A growing shape stops when it touches another mark's space, the edge, or when ink runs out. - Choose a shape with the buttons or keys **1–4**. - **Keyboard only:** arrow keys move the cursor, **hold Space** (or Enter) to grow, release to stamp. - **M** switches between *Claimed* mode (marks block space) and *Free* mode (marks may overlap). **R** restarts. ## Where the premises live (script.js) - **Agency:** `startGrowing()`, `grow()`, `commit()`. The participant chooses where, how big and which shape every mark is. - **Possibility:** `spaceLimit()`, `inkLimit()`, `anyRoomLeft()`. Every mark claims space and spends ink, and these limits come from the participant's own earlier marks. - **Comparison:** *Claimed* vs *Free* mode differ in one rule only (`knobs.blockSpace`). - All numbers and rules are in the `knobs` object at the top of `script.js`. ## Credits - Code, layout and shapes: my own, written with AI assistance (see note below). - The `knobs` settings-object structure follows the NMED 3203 Interactive Media Applications lab experiments. - No external assets or libraries. ## AI note I used Claude (Anthropic) to compare premise pairs, to write the HTML/CSS/JavaScript, to explain the code to me, and to draft the rationale text, which I then checked against the two readings myself.
